# 跨平台矩阵（0.2.0 起）

> 这份文件把 `ROADMAP.md` 第六节那张表展开成正文。**每一格回答四件事**：怎么实现、需要什么权限、失败时什么样、用户怎么自救。
> 矩阵是**计划**，不是实测结果。没有标「实测」的格子都算未验证 —— 怎么验在第十节，哪些还没验在第十二节。
> 最后更新：2026-11-24

## 一、先读这一条：形态由宿主决定，不由设置决定

| 宿主是什么 | 实验室跑成什么 | 画面从哪来 |
|---|---|---|
| 桌面版（Electron） | 第二个 Electron 实例，同一个可执行文件，独立 `--user-data-dir` 与 `DSH_HOME` | 实验室里的插件 `webContents.capturePage()` |
| `dsh web`（浏览器打开） | headless 进程（0.1.x 的老形态） | 不需要帧，面板直接嵌它的 HTTP 页面 |

为什么不做 web / desktop 二选一的开关：两条完整代码路各自要维护与验收，而「宿主是不是桌面版」本来是客观事实，让用户选只会选错。判据只有两条 —— 宿主本身有没有 Electron、这台机器有没有图形会话。

## 二、总表

| 能力 | Windows | macOS | Linux X11 | Linux Wayland | 无图形会话 |
|---|---|---|---|---|---|
| 第二桌面实例 | 可用 | 可用 | 可用 | 可用 | 不适用 |
| 帧推送（`capturePage`） | 可用 | 可用 | 可用 | 可用，且**不走 portal** | 不适用 |
| 输入注入（`sendInputEvent`） | 可用 | 可用 | 可用 | 可用 | 不适用 |
| 系统权限需求 | 无 | 默认路线无（备用路线见第四节） | 无 | 无 | 无 |
| 资源限额采样（0.2.1） | `tasklist` | `ps` | `ps` | `ps` | `ps` |
| 无图形会话兜底 | 不适用 | 不适用 | 自动 `web-core` | 自动 `web-core` | 就是这条本身 |
| 验证状态 | 部分实测（0.1.x 的 headless 路径） | 待实测 | 待实测 | 待实测 | 待实测 |

「不适用」不等于做不到，而是那个格子没有意义：Windows 不会没有图形会话，无图形会话也不会有窗口可抓。

## 三、Windows

**怎么实现**。宿主用 `process.execPath`（桌面版就是 Electron 本体）起第二个实例，参数是 `[--user-data-dir, <lab>/userdata]`，环境变量只带白名单里的几项再加 `DSH_HOME=<lab>/home`。实验室里装一个插件，它定时 `webContents.capturePage()` 取自己这一页的 JPEG，经宿主端点推给面板；面板采集鼠标键盘，顺着同一条通道回去，插件调 `webContents.sendInputEvent()`。

**需要什么权限**。无。这一点值得说清：`capturePage` 拷的是**本进程 WebContents 的合成结果**，不是屏幕缓冲区；`sendInputEvent` 直接把事件送进 renderer 的输入管线，不经过系统的 `SendInput`。所以两条都不触碰任何安全边界，也就不需要授权。

**失败时什么样 / 怎么自救**。

| 症状 | 机制 | 自救 |
|---|---|---|
| 帧全黑 | 实验室窗口被最小化：最小化后该窗口不再合成，`capturePage` 取到空帧 | 插件在最小化时暂停推帧，面板显示「已暂停」；把窗口恢复即续帧。别用「最小化」当隐藏手段 |
| 窗口被别的窗口完全遮住却是黑帧 | Electron < 25.9.2 的老问题（Windows/Linux 都已修，[v25.9.2](https://releases.electronjs.org/release/v25.9.2) 的 #40186） | 确认宿主 Electron 版本；我们的下限远高于它，正常不会遇见 |
| 帧冻住不动 | 推帧通道断了，重连在指数退避中 | 面板角标显示重连中；「⋯ → 刷新」强制重建 |
| 画面正确，点击偏一格多 | 坐标空间搞混，见第九节 | 用画面里一个已知控件自校：点它，看落点 |
| 进程起来但没有窗口 | 宿主跑在会话 0（服务、计划任务）里：有窗口概念、没有交互桌面 | 见第七节；这种情况不在兜底范围 |

## 四、macOS

这一节最容易被写成「要屏幕录制权限」。分清楚是哪条路线要走权限：

| API | 走不走系统授权（TCC） | 谁需要它 |
|---|---|---|
| `webContents.capturePage()` | 不走：拷的是本进程渲染结果 | **默认路线（我们这条）** |
| `desktopCapturer` / `getDisplayMedia()` | 走：屏幕录制 | 备用路线（`capturePage` 出黑帧时） |
| `webContents.sendInputEvent()` | 不走：进程内输入管线 | **默认路线（我们这条）** |
| `CGEvent` / 辅助功能注入 | 走：辅助功能 | 备用路线（系统级注入鼠标键盘时） |

**所以默认路线在 macOS 上不需要任何授权。** `ROADMAP.md` 第六节那格写的是「首次要屏幕录制权限」，那是**备用路线的代价**，被压在一格里容易被误读成默认行为；真机第一次跑要复核，复核办法见第十节。

**如果真到了备用路线**。

| 权限 | 在哪给 | 拒绝时什么样 | 自救 | 怎么撤 |
|---|---|---|---|---|
| 屏幕录制 | 系统设置 → 隐私与安全性 → 屏幕录制 | 不报错：`desktopCapturer.getSources()` 返回空列表，或帧全黑 | 授权后要让实验室**换一个新进程**（面板「重启」，或停止再启动）—— TCC 的改动只对新进程生效；保险起见重启宿主 | 在系统设置里取消勾选；下次会重新问一次 |
| 辅助功能 | 系统设置 → 隐私与安全性 → 辅助功能 | 能看不能点：帧照常，输入全部丢弃 | 同上，换个新进程；`systemPreferences.isTrustedAccessibilityClient(true)` 可查状态并弹一次引导 | 同上 |

三条与授权有关的硬事实：

- **同一个 `.app` 一次授权对两个实例都生效**：TCC 认 bundle 身份，不认 pid。所以不必给实验室单独开权限，也不必为了它再点一遍允许。
- **换了 `.app` 的位置会丢掉授权**：TCC 认路径与签名。把桌面版从「下载」挪到「应用程序」之后，屏幕录制那条要重新授权；升级插件本身不影响。
- **拒绝是静默的**：两条权限都不会抛异常，只表现为「空帧」或「点了没反应」。查症状时先看这两项状态，别先怀疑代码。

**其他差异**。菜单栏会多一个托盘图标（`Tray` 是每进程一份，实验室那个实例有自己的）。Dock 里是否多一个图标取决于两个进程是不是同一个 `.app` 包启动，待实测。多显示器不影响：`capturePage` 只拿这一页，与屏幕布局无关。

## 五、Linux X11

**怎么实现**。与 Windows 同一条代码路：第二个 Electron 实例 + 插件推帧 + `sendInputEvent`。

**需要什么权限**。无。X11 下抓屏本身不需要额外授权，但 OS 级输入注入在 X11 上是全局的（谁都能往任何窗口送事件）—— 我们不用那条路，用不上这个「方便」。

**失败时什么样 / 怎么自救**。

| 症状 | 机制 | 自救 |
|---|---|---|
| 没有窗口，日志里 GPU / EGL / Vulkan 报错 | 无 GPU 或驱动缺失，Electron 起不来 | 关掉 GPU 加速（是否做成配置项待定）；连续失败就退回 headless |
| 起来但画面白或花 | 软件渲染下 `capturePage` 的时序（首帧还没合成完） | 等一帧再抓（T3 的定时器天然覆盖）；「刷新」重建 |
| 连不上显示 | `DISPLAY` 设错或指到 SSH 转发的假 X server | `echo $DISPLAY`；没有真屏幕就按第七节处理，别当桌面跑 |
| 实验室与宿主抢同一个 X server 的焦点 | 两个都是独立窗口，正常现象 | 面板「启动」后点回宿主页面 |

## 六、Linux Wayland

**为什么默认不用 portal**。Wayland 不给任何进程看别人的画面：要么走 `xdg-desktop-portal` + PipeWire，而那条每次抓屏都要用户点一次「允许共享」；要么就别抓。我们抓的是实验室**自己**这一页（`capturePage`），所以：不弹授权框、不每次问、也不做屏幕录制。

代价只有一个：**抓不到实验室窗口以外的任何东西** —— 窗口装饰、系统菜单、其它应用都不在帧里。面板要显示的只是页面本体，这个代价等于零。

**输入**。`sendInputEvent` 在进程内，Wayland 不拦。反过来说，Wayland 禁止全局键盘钩子与全局注入，所以「宿主侧抓窗口 + OS 级注入」那条路在 Wayland 上根本不成立 —— 这也是选「实验室自己推帧」路线的直接理由，不只是为了省权限。

**失败时什么样 / 怎么自救**。

| 症状 | 机制 | 自救 |
|---|---|---|
| 实验室实际跑在 XWayland 下 | Electron 不加 `--ozone-platform=wayland` 时可能由 XWayland 承载 | 不影响 `capturePage` 与 `sendInputEvent`；不用管。要原生 Wayland 再加参数（待定） |
| `DISPLAY` 与 `WAYLAND_DISPLAY` 都空 | 判定为无图形会话 | 自动 headless（第七节），面板照旧能看日志、能驱动 |
| 帧率比 X11 低 | 合成器 vsync 与省电策略管着帧；不是我们的定时器 | 降推帧频率（插件侧可配），别指望 60 fps |
| 分数缩放（125% / 150%）下画面糊 | 帧按整数倍缩放再压 JPEG | 提高 JPEG 质量或按倍数放大帧尺寸；坐标仍走第九节的规则 |

## 七、无图形会话

**判据**：Linux 且 `DISPLAY` 与 `WAYLAND_DISPLAY` 皆为空 → `web-core`；Windows / macOS 恒 `desktop-shell`。日志会留一行说明走了兜底。

**为什么这是兜底不是开关**。「有没有屏幕」是客观事实，用户选不出一朵花来；把它做成选项，只会出现「明明没屏幕却选了桌面形态」这种必然失败的组合。

**正常样子**：面板里是 iframe（0.1.x 的形态），没有镜像画面。在只有 SSH 的 Linux 机器上这是**正确形态**，不是缺陷。实验室该有的都在：装插件、看日志、`report`、`lab_ui` 驱动界面。

**不在兜底范围的一种情况**：Windows 的会话 0（服务、计划任务里跑宿主）。它有窗口概念但没有交互桌面，Electron 起来会立刻退出 —— 面板显示「已崩溃」，日志里有 GPU / 初始化错误。自救只有两条：别在服务里跑宿主；或者退回 0.1.5（那时只有 headless）。

**做不到的那件事**：无屏幕的机器上「看见界面并点」不可能。答案与隔离边界那节是同一条：换一台机器，或换远程主机。

## 八、跨平台共用的失败形态

先看这几条，再分平台：

| 症状 | 最可能的原因 | 自救 |
|---|---|---|
| 面板「运行中」但没有画面 | 推帧通道没接上 | 看实验室日志有没有插件那行；`report` 的 `declared` 里查显微镜插件在不在 profile 里 |
| 有画面，点击偏 | 坐标空间搞混（第九节） | 用已知控件自校 |
| 在画面里拖选，结果选中了宿主页面的文字 | 指针事件没被 `MirrorView` 吃掉，冒泡到宿主页面 | 面板底带「锁定」挡输入；根治在组件层（吃掉并 `preventDefault`），不该让用户绕 |
| 面板和实验室两个窗口来回抢焦点 | 第二个实例启动时会抢一次焦点 | 已知代价，启动后点回宿主 |
| 实验室起来了，正式版 DSH 行为变怪 | 两个实例抢单实例锁 / 托盘 / 更新检查 | 各自的 `user-data-dir` 不同，单实例锁按目录分；若仍异常，先停实验室确认 |

## 九、坐标与尺寸：唯一要写死的规则

**帧的尺寸与输入的坐标全程用 DIP（`NativeImage.getSize()` 的返回值），不要用 `toBitmap()` 的像素数。**

为什么：`capturePage(rect)` 的 rect 是 DIP，`sendInputEvent` 的 x/y 也是相对 WebContents 的 DIP。同一个空间里进出，跨平台天然一致。一旦某一步换成了 bitmap 像素，就得按 `devicePixelRatio` 折算，而这一步没人会记得 —— 150% 缩放下表现就是「点偏一格半」，在 100% 缩放的机器上看不出来，于是被当成「偶发」。

| 层 | 单位 | 注意 |
|---|---|---|
| `capturePage(rect)` | DIP | rect 给 `{x:0,y:0,width,height}` 即整页 |
| `NativeImage.getSize()` | DIP | 帧消息里的 `w`/`h` 用它 |
| `NativeImage.toBitmap()` | 设备像素 | **不要**把它的尺寸塞进输入坐标 |
| canvas 的 CSS 尺寸 | CSS px | 与 DIP 同数，不用折算 |
| `sendInputEvent` 的 x/y | DIP | 窗口内坐标，不是屏幕坐标 |

自校办法：面板里点实验室界面上一个位置固定的控件（比如右上角第一个按钮），看光标是否落在它身上；偏了就先怀疑这一节。

## 十、怎么验一台新机器

按顺序跑，每条都有判据：

| # | 动作 | 判据 |
|---|---|---|
| 1 | `node -e "console.log(process.platform, process.env.DISPLAY, process.env.WAYLAND_DISPLAY)"` | 先确定该走哪一格 |
| 2 | 创建实验室 → 启动 | 面板到「运行中」；桌面形态下多一个窗口 |
| 3 | 看画面 | 有画面 = 推帧通道通；黑帧先查窗口是否最小化与第四节的两项权限 |
| 4 | 在画面里点一个会改变状态的控件 | 实验室里状态真的变（不是「看起来点了」） |
| 5 | 最小化实验室窗口 30 秒再恢复 | 期间不崩、不卡死，恢复后续帧 |
| 6 | 关宿主 → 重开宿主 | 实验室能重连或自动重启，`labs.json` 记录不丢 |
| 7 | 让实验室吃内存（0.2.1 起） | 实验室被停且有日志写明原因，宿主内存曲线不抖 |
| 8 | macOS 上有没有被要求授权 | 没被要求 = 默认路线；被要求 = 走了备用路线，按第四节处理 |

第 8 条是这次最需要真机回答的问题：它决定 README 与本节要不要改口径。

## 十一、权限一览

| 平台 | 默认路线需要 | 只有备用路线才需要 |
|---|---|---|
| Windows | 无 | 无（真做 OS 级注入才涉及 UIPI 放行） |

| Linux X11 | 无 | 无 |
